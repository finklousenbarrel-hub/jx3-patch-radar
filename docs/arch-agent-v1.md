# Agent 架构设计 v1

## 1. 现状与问题
- ask.py 现状：单检索器 RAG，所有问题都走同一个 TF-IDF top-3
- 痛点：问"版本哪个DPS强"时检索器根本够不到强度榜数据（数据形态不是文档是表格）

## 2. 工具清单（每个工具：名称/入参/返回/数据源）
- query_skill：技能库检索（现有 retriever，技能文档）
- query_patch：技改库检索（现有 retriever，技改文档）
- query_meta_rank：心法强度榜查询（新，来自 022 管道的快照）
    1. segment 默认2800-3100（高分段更有参考价值），但如果用户有提及某一个指定分段可按其指定分段进行查询。
    2. match_type 默认组队匹配 如果用户有提及散排则使用单人匹配或all（视具体语境而定）
    3. time_range 默认近7日（防止技改前的数据影响决策）

## 3. 路由策略（核心决策点）
- 方案A：LLM function calling 自主选工具（Moonshot 支持 tools 参数）
- 方案B：规则路由（关键词匹配先行）
- 我的选择与理由：
    A
    1. 规则路由没办法穷尽所有的问询关键字，必须要大模型通过自己的语义理解来调用工具。
    2. 规则路由无法做到并行工具调用
    3. 代价为模型幻觉（可注入prompt解决）与偶发失误（可以接收的范围内）

## 4. 失败防御
- 工具返回空数据怎么办
    检查是本身没有数据还是管线存在问题
- 模型编造工具没返回的数据怎么办
    1. 规范层：在agents.md里明令禁止，并对数据做一轮审查（Agents审）
    2. 工程层：回答必须逐条对应工具返回
    3. 设计评测层，询问资料库里没有的问题
- ticket 过期/接口超时怎么办
    走流程：检测 → 明确报错 → 人工更新 → 恢复

## 5. 评测设计（对接 D38 评测集）
- 10 题分布 = 
        3 技能（含 1 条错别字/简写）
        + 3 技改 
        + 2 强度榜 
        + 1 复合（多工具连调）
        + 1 拒答
